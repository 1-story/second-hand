# 数据库设计文档 — 校园二手交易平台（第二手 SecondHand AI）

> 设计人：田博（后端） · 版本：V1.1（数据库切换 PostgreSQL） · 适用 PostgreSQL 15/16
> 建表脚本：`sql/schema.sql`（可直接执行，含种子数据）

---

## 1. 设计规范

| 项目 | 约定 |
|------|------|
| 数据库 | `second_hand`（PostgreSQL，UTF-8 默认编码） |
| 主键 | `id BIGINT GENERATED BY DEFAULT AS IDENTITY`（自增） |
| 时间 | `created_at`/`updated_at`（TIMESTAMP）；`updated_at` 由统一触发器 `set_updated_at()` 自动维护 |
| 删除 | 逻辑删除 `deleted SMALLINT(0/1)`（业务数据不物理删除，便于审计与恢复） |
| 金额 | `DECIMAL(10,2)` 元；禁止 FLOAT/DOUBLE 存金额 |
| 状态 | SMALLINT + 代码注释枚举，业务层用常量类约束 |
| 命名 | 表/字段蛇形命名（snake_case）；外键逻辑关联不建物理外键（便于分表与迁移） |
| JSON | 原生 `JSONB` 类型（估价明细/草稿数据） |
| 检索 | `pg_trgm` 扩展 + GIN 索引（中文近似匹配），业务层 LIKE/ILIKE 兜底 |
| 索引 | 唯一键 uk_*、普通索引 idx_*，检索高频组合建联合索引 |

## 4. 关键设计说明

### 4.1 商品状态机（product.status）
```
0 草稿 ──发布──▶ 1 在售 ──成交──▶ 3 已售出
  │                │
  └──删除(逻辑)      ├──下架──▶ 2 已下架 ──重新上架──▶ 1
                    ├──审核──▶ 4 审核中 ──通过──▶ 1 / ──驳回──▶ 5
```
- AI 一键发布链路：草稿（ai_publish_draft）确认后进入 `4 审核中`（AI 辅助审核，V1.0）或直接 `1 在售`（配置开关 `ai.audit-on-publish`）。

### 4.2 AI 估价参数落库（category）
估价公式所需的基准价、折旧率、热度系数全部来自分类表，**改价不改代码**，运营可在管理后台维护。

### 4.3 信用分（user_credit + user.credit_score）
- `user.credit_score` 为冗余汇总（查询展示快），真实流水在 `user_credit`，以流水为准。
- 分值规则（示例，V1.0 细化）：交易成功 +2、好评 +1、差评 -3、违规 -10、举报成立 -5、申诉恢复按流水回补。

### 4.4 中文检索（PostgreSQL）
- 建 `pg_trgm` 扩展，对 `product.title` / `product.description` 建 GIN 索引（`gin_trgm_ops`），支持中文近似/模糊检索；
- 业务层检索用 `LIKE`/`ILIKE` 兜底，与索引配合；
- 如需更强的中文分词，可在 V1.0 引入 `zhparser` 扩展（可选，不影响现有实现）。

### 4.5 自动更新时间
PostgreSQL 无 MySQL 的 `ON UPDATE CURRENT_TIMESTAMP`，统一由触发器函数 `set_updated_at()` 维护所有含 `updated_at` 的表（建表脚本末尾统一创建）。

### 4.6 与成员模块的衔接
- `user` 表仅基础字段，密码/Token 由陈思瀚登录模块扩展（同表加列即可）。
- `message`/`carbon_record`/`carbon_credit` 已按约定建好，林天楚模块直接使用。
- 订单/互评表先建好结构，V1.0 联调时按交易流程补充接口。

## 5. 索引与性能说明
- 高频查询路径均已覆盖：卖家商品（seller_id+status）、分类浏览（category_id+status）、最新发布（status+created_at）、价格区间（price）、收藏幂等（唯一键）、足迹（user_id+last_view_at）。
- 全表数据量预期为校园级（万级），上述索引足够；如商品量增长，可扩展 ES 检索（V1.0 后）。
