### 3. Git 分支/提交规范（建议，待组长定稿）

- 分支模型（简单化，适合 5 人课程项目）：
  - `main`：可验收主分支，仅合并测试通过的代码
  - 每人一个功能分支：`feature/<姓名拼音>-<模块>`，如 `feature/tianbo-product`、`feature/tianbo-ai`
  - 合并前在本地跑 `mvn -s settings.offline.xml -f pom.verify.xml test-compile`（离线编译检查）
- 提交信息格式：`<类型>(<模块>): <说明>`，类型用 `feat/fix/docs/test/refactor/chore`
  - 例：`feat(product): 实现商品分页检索接口`
- 文件约定：`maven-repo/`、`target/` 已加入 `.gitignore`，不提交

### 4. 统一接口响应结构 + 错误码（已实现，请组长确认）

统一返回体（所有接口）：

```json
{ "code": 200, "message": "操作成功", "data": { } }
```

| code | 含义 |
|------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未登录/登录过期 |
| 403 | 无权操作 |
| 404 | 资源不存在 |
| 409 | 资源状态冲突 |
| 500 | 服务器内部错误 |
| 1001~1007 | 用户/商品/分类/收藏业务错误 |
| 1101~1104 | AI 业务错误 |

分页统一为 `PageResult{records,total,page,size,pages}`。实现位置：`common/Result.java`、`common/ResultCode.java`、`common/GlobalExceptionHandler.java`。

> 待陈思瀚确认：错误码是否全队统一使用 `common/ResultCode` 这份定义？登录模块接入后 401 语义由我这边保持兼容。

| 页面 | 负责前端 | 后端接口 | 接口负责人 |

| AI 智能发布表单 | 徐家凯 | `POST /api/ai/identify`、`/api/ai/describe`、`/api/ai/estimate`（识别+描述+估价） | 田博 |
